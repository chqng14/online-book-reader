# Folio — Online Book Reader

A private, browser-local reading library with a Vietnamese interface. The visual direction is inspired by [Impeccable](https://impeccable.style/): neutral paper surfaces, near-black typography, gold accents, fine rules and restrained controls. Be Vietnam Pro adapts the sans-serif direction for full Vietnamese coverage. Reading features take inspiration from Apple Books; this is an independent web application, not an Apple product or a complete Apple Books clone.

## Start locally

Requires Node.js 22.13+ (a current LTS release is recommended).

```sh
npm ci
npm run setup
npm start
```

Open http://localhost:3000. Serve the `dist/` folder over HTTPS in production. There is no API server, account system, database server, or build step. `npm run setup` copies pinned third-party dependencies into the static site and downloads the two locally served font files. No CDN is contacted while reading.

## Features

- Import multiple books or drop files onto the library. SHA-256 content hashes prevent duplicates.
- EPUB: metadata, raster covers and illustrations, reading order, EPUB 2/3 table of contents, chapter links.
- PDF: original page rendering with PDF.js, searchable extracted text, optional text reading mode.
- TXT (UTF-8), basic Markdown, sanitized HTML, and FB2.
- Grid/list library, title/author search, sorting, favorites, reading/finished filters, custom collections.
- Resume chapter and scroll position; bookmarks; text highlighting; editable notes; full-book text search.
- White, sepia, and night reader themes; font family, font size, line spacing and page width controls.
- Arrow keys / Page Up / Page Down and horizontal touch gestures; fullscreen when supported.
- Daily reading goal, measured while the reader is visible and recently active (three-minute inactivity cutoff).
- Download original files; export and restore a ZIP containing books, progress, bookmarks, notes, collections and preferences. Existing duplicate books are kept unchanged during restore.
- Optional persistent-storage request and browser-storage usage estimate.
- Self-hosted static assets and service-worker caching. The shell and main reader libraries can be reopened offline after a successful online load; PDF-specific resources are cached as encountered. Offline behavior is subject to browser and hosting authentication policy.
- Feature-detected WebMCP tools for listing and opening existing local books.

## Storage and privacy

IndexedDB stores book metadata and original/parsed contents in separate object stores. Imported book data is never sent to an application server. Preferences, collections, annotations and reading statistics are device-local. Normal website requests still go to the hosting provider.

Browser storage belongs to the exact origin. Changing the domain, browser profile, or device does not carry the library with it. Clearing site data or private browsing may remove it. Persistent storage is best-effort, not a backup. Keep original files and export backups. Test-sample annotations are session-only and do not enter the library.

## Scope and limits

- Files: up to 50 MB each. ZIP expanded size guard: 160 MB. PDF: at most 2,500 pages. Backup export: up to 150 MB of original files. Backup import: at most 200 MB compressed and 160 MB expanded.
- No DRM, MOBI/AZW, store, cloud sync, audiobook library, OCR, or cross-device handoff.
- EPUB publisher CSS, scripts, embedded media, SVG, remote images and active content are intentionally not rendered. Semantic text and common raster images are retained. Complex fixed-layout or vertical-writing EPUBs may not preserve their layout.
- PDF text mode depends on an existing text layer. Text reading order can differ from the original page. Highlighting/notes apply in PDF text mode, not directly on the canvas. Scanned PDFs remain readable in page mode but are not OCR-searchable.
- Markdown supports headings, paragraphs, bold text and inline code; it is not a full CommonMark renderer.
- Scroll position is stored as a chapter-relative fraction; changing font size can shift the exact sentence restored.
- The service worker cannot guarantee offline access through an authentication gateway.

## Project structure

```text
dist/index.html       Accessible app shell
dist/styles.css       Library and reader design, responsive styles
dist/app.js           UI, reading state, search, notes, backup, WebMCP
dist/parsers.js       EPUB/PDF/TXT/MD/HTML/FB2 parsing and sanitization
dist/storage.js       IndexedDB transactions
dist/sw.js            Offline asset cache
dist/vendor/          Third-party browser assets (generated by setup)
dist/fonts/           Self-hosted Be Vietnam Pro fonts
scripts/setup.mjs     Prepare static vendor assets
scripts/serve.mjs     Local development server
tests/integration.mjs DOM and storage integration checks
```

`dist/` contains authored source, not disposable build output. Do not delete it as build cleanup.

## Validation

```sh
npm run check
npm test
```

Integration tests use DOM simulation and fake IndexedDB. They exercise EPUB metadata/TOC parsing, unsupported/corrupt inputs, sanitization, text formats, atomic persistence/deletion, opening/resuming, bookmarks/highlights, search, favorites, collections, backup round trips, and the WebMCP tools. They do **not** validate browser rendering, real browser quota policies, mobile layout or fullscreen. Browser visual/end-to-end QA has not been performed.
